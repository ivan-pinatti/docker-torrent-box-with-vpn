# Build

Container images this repository builds itself, rather than pulling ready made.
Each is a thin wrapper over a third-party base image that adds one thing the
published image does not carry.

These Dockerfiles are written and maintained here, unlike
[`patches/`](../patches/README.md), which holds vendored upstream source. That
distinction decides how the linters treat each tree: `patches/` is excluded
from them wholesale because reformatting someone else's code is not our
business, while everything here is linted normally.

## Contents

| Directory | Base image | What it adds |
| --- | --- | --- |
| `lazylibrarian/` | `linuxserver/lazylibrarian` | Calibre, from the `linuxserver/mods:universal-calibre` image, so LazyLibrarian can convert and import ebooks |
| `mylar/` | `linuxserver/mylar3` | `pyOpenSSL`, which Mylar needs to talk to qBittorrent over HTTPS with a self-signed certificate |

Neither takes a default `BASE_VERSION`. Compose always passes one from the
matching `*_VERSION` in `.env`, and a bare `docker build` should fail loudly
rather than quietly produce an image built on `:latest` that no longer matches
the pinned version.

## Why the suppressions are spread across three files

Three scanners read these Dockerfiles, and each one only honours its own
suppression mechanism, so the same fact is stated three times:

| Finding | Tool | Where the suppression lives | Why there |
| --- | --- | --- | --- |
| `DS-0002`, `DS-0026` | trivy | `.trivyignore.yaml` | Whole-file checks, so trivy's inline `#trivy:ignore:` comments are silently ignored. Only the YAML form supports scoping a suppression to a path |
| `CKV_DOCKER_2`, `CKV_DOCKER_3` | checkov | Inline in each Dockerfile | checkov's inline `#checkov:skip=` comment does work for these |
| `DL3008`, `SC2046` | hadolint | Inline in `lazylibrarian/Dockerfile` | hadolint's inline `# hadolint ignore=` applies to the next instruction, which is the correct scope here |

The first two say the same thing: linuxserver.io images run their s6-overlay
init as root and drop to the `PUID`/`PGID` identity themselves, so a `USER`
instruction would break startup before the app runs, and health is defined per
service in the compose files where it can probe the real endpoint and port.

The hadolint pair is narrower and applies to one `RUN` instruction. Its package
list is generated by the Calibre mod's own init script rather than written
here, so there is no version to pin, and the command substitution holding that
list has to word-split into separate arguments, so quoting it would turn the
whole list into one nonexistent package name.

Suppressing per instruction rather than excluding this directory is deliberate.
An exclusion would also drop the checks that have caught nothing yet but are
the reason the linter is here at all: an unpinned base tag, `cd` where
`WORKDIR` belongs, and shellcheck over `RUN` lines, which is shell that the
`shellcheck` hook never sees because it selects `.sh` and `.bash` files.
